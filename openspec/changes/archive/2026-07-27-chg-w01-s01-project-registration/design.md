## Context

Wave `w00` is complete and archived: governance validators, Nx monorepo (`apps/web`, `apps/api`, `packages/shared-contracts`), PostgreSQL + Prisma with Compose local runtime, and mandatory local quality gates with post-push CI. Persistence today is a probe-only `AppMetadata` model; the API exposes liveness/readiness only; the web app is a SpecPilot-branded baseline shell without product domain screens.

Wave `w01` begins with slice `w01-s01-project-registration`: SpecPilot must register and validate local macOS repositories as durable `Project` records so later slices can attach configuration snapshots (`w01-s02`), Git/OpenSpec discovery (`w01-s03`), and a dashboard (`w01-s04`). ADR-003 (PostgreSQL-only) and ADR-005 (portable `.specpilot/project.yaml`; absolute paths live only in SpecPilot DB) are binding. The product remains read-only toward target repositories.

Stakeholders: SpecPilot operator (human validation and approvals); Cursor (sole implementer). Main-only working policy and operator approval gates remain binding.

## Goals / Non-Goals

**Goals:**

- Persist a bounded `Project` domain model in Prisma/PostgreSQL while retaining the existing `AppMetadata` probe.
- Accept a local absolute repository path, validate registration eligibility fail-closed, and create a durable project record whose `repositoryPath` identity is the filesystem **realpath**-canonical absolute directory.
- Require `.specpilot/project.yaml` **presence** (regular file under the canonical directory) without full YAML parse/schema validation.
- Expose shared request/response contracts plus NestJS API and a minimal Spanish-first Angular registration flow with explicit success, blocked, empty, loading, and error outcomes.
- Keep target repositories read-only (no writes, no command execution inside them).
- Deliver deterministic automated evidence for success and at least one blocked/failure path; keep quality gates green.
- Update docs/context inventory and package summary as needed.

**Non-Goals:**

- Full `project.yaml` parse, schema validation, versioning, or `ProjectConfigurationVersion` snapshots (`w01-s02`).
- Git status / OpenSpec discovery inspection (`w01-s03`).
- Project dashboard or discovery-health UI (`w01-s04`).
- Editing target repositories; running Git, OpenSpec, Cursor, tests, commits, or delivery commands from SpecPilot.
- Storing an alternate symlink path as an additional identity alongside the canonical realpath in this slice.
- Remote repositories without a local checkout; Windows/Linux support.
- Authentication/multiuser; DeepSeek product API; reviews, findings, budget, prompts, context bundles.
- Removing or replacing the `AppMetadata` probe; introducing Redis/SQLite or non-PostgreSQL stores.
- Editing OpenSpec-generated integrations except via `openspec update`.

## Decisions

### D1 — Domain model: `Project` only; keep `AppMetadata`

Add a Prisma `Project` model mapped to `projects`, additive migration only. Retain `AppMetadata` unchanged as the persistence-plane probe.

Binding fields for this slice:

| Field | Storage | Notes |
|---|---|---|
| `id` | UUID (`projectId`) | Primary key generated by SpecPilot |
| `slug` | unique lowercase kebab-case | Machine identity; unique DB constraint |
| `displayName` | string, max **120** chars | Operator-facing label; **not** unique |
| `repositoryPath` | unique canonical absolute path | Filesystem **realpath** of the real directory; unique DB constraint; never written into YAML |
| `status` | enum/string | Initial value `registered` |
| `registeredAt` | timestamptz | Set on create |
| `lastInspectedAt` | nullable timestamptz | Null until discovery (`w01-s03`) |
| `configurationVersionId` | omitted | Deferred to `w01-s02` (no FK/column yet) |

PostgreSQL **unique constraints** on `repositoryPath` and `slug` are mandatory and are the final concurrency guarantee (see D10).

- *Alternative considered:* introduce `ProjectConfigurationVersion` now. Rejected — belongs to `w01-s02`.
- *Alternative considered:* drop `AppMetadata`. Rejected — still proves readiness/migration probe independently of product data.

### D2 — Registration identity: canonical path + derived slug; optional display name

Registration request carries:

- `repositoryPath` (required): absolute local path string from the operator (validated as absolute before any filesystem work).
- `displayName` (optional): see binding rules below.

**Persisted path identity (binding):**

- Validate the received path as absolute first (`empty_repository_path` / `relative_repository_path` when not).
- After confirming the target exists, obtain identity via filesystem **realpath** (follow symlinks only to resolve the real target).
- Persist `repositoryPath` as the **canonical absolute path of the real directory**—not merely `path.resolve`, and not the raw textual form the operator typed.
- Trailing slashes and redundant segments MUST disappear through that canonicalization.
- Two different textual paths or symlinks that resolve to the same real directory are the **same** repository and MUST block as `duplicate_repository_path`.
- Do **not** store a symlink alternate path as an additional identity in this slice.

**Slug:**

- Derived from the **basename of the canonical directory** normalized to lowercase kebab-case.
- If that basename cannot yield a valid kebab-case slug, registration is blocked with `invalid_derived_slug` (no insert). Explicit slug override is out of scope.

**displayName (binding):**

- Optional on the request.
- Apply `trim`.
- If omitted or empty after trim, default to the basename of the **canonical** directory.
- Maximum length is **120** characters (stable across shared contract, Prisma column/`@db` limit, and tests).
- `displayName` does **not** participate in uniqueness.
- Values exceeding 120 characters after trim → blocked validation `invalid_display_name`; no row inserted.

- *Alternative considered:* require operator-supplied slug on every register. Rejected — extra friction for the common case; basename-derived slug matches local-first repo naming.
- *Alternative considered:* read `project.id` / `project.name` from YAML now. Rejected — content parsing is `w01-s02`; presence-only keeps the slice boundary clean.
- *Alternative considered:* store both symlink path and realpath. Rejected — single canonical identity only in this slice.
- *Alternative considered:* uniqueness on `displayName`. Rejected — operator labels may collide harmlessly.

### D3 — Preflight validation (fail-closed, read-only filesystem)

Before insert, a dedicated filesystem port (adapter over Node `fs`) performs, in order:

1. Reject empty/whitespace paths → `empty_repository_path`.
2. Reject non-absolute paths → `relative_repository_path` (no silent acceptance of relative paths; do not treat `path.resolve` alone as identity).
3. Confirm the path exists → else `repository_not_found`.
4. Obtain **realpath** (follow symlinks only to resolve the real target).
5. Confirm the canonical target is a **readable directory** → else `repository_not_directory` or `repository_not_readable` as applicable.
6. Resolve `.specpilot/project.yaml` **inside the canonical directory**; confirm it exists as a **regular file** (presence only—do not parse contents) → else `project_yaml_missing` or `project_yaml_not_regular_file`.
7. Apply `displayName` trim/default/max-length rules → `invalid_display_name` when over max.
8. Derive slug from canonical basename → `invalid_derived_slug` when invalid.
9. Precheck for an existing Project with the same canonical `repositoryPath` or derived `slug` to improve operator feedback (see D10: precheck does **not** replace unique constraints).

Any blocked validation returns the structured error contract and MUST NOT create a partial row. The adapter MUST only perform read/`stat`/`access`/`realpath`-class operations—never create, modify, or delete files in the target repository.

SpecPilot does not sandbox the operator’s chosen path beyond eligibility checks (local trust model, no auth).

- *Alternative considered:* accept registration without YAML and mark status `incomplete`. Rejected — ADR-005 / product scope require the contract file; fail closed.
- *Alternative considered:* parse and validate full YAML schema during registration. Rejected — `w01-s02` scope.
- *Alternative considered:* identity via `path.resolve` without realpath. Rejected — allows duplicate rows for symlink/alias paths to the same directory.

### D4 — Modular monolith: Projects module + ports/adapters inside `apps/api`

Implement under `apps/api`:

- `ProjectsModule` with controller, application service, Prisma repository adapter, and filesystem preflight adapter.
- Domain/application logic depends on ports (interfaces), not on Nest/Prisma/fs directly in the core validation/register use case where practical.
- No new Nx library package yet; shared DTOs live in `packages/shared-contracts`. Prisma remains owned by `apps/api` (unchanged from `w00-s03` D1).

Nx tags/boundaries from `w00-s04` continue to apply: web may depend on shared-contracts; web MUST NOT import API internals; API MUST NOT import web.

- *Alternative considered:* extract `packages/project-registry` now. Rejected — single consumer; premature package split.
- *Alternative considered:* put registration logic only in the controller. Rejected — harder to unit-test fail-closed preflight independently of HTTP.

### D5 — API contracts (shared-contracts + Nest/Fastify)

Add TypeScript contracts (and lightweight runtime validators/type guards consistent with the existing health-contract pattern; no Zod unless a later change documents necessity) in `packages/shared-contracts`:

- `RegisterProjectRequest`: `{ repositoryPath: string; displayName?: string }`
- `ProjectDto`: `{ id, slug, displayName, repositoryPath, status, registeredAt, lastInspectedAt }` (`repositoryPath` is always the canonical realpath stored)
- `ProjectErrorResponse` (stable for all blocked/error outcomes): `{ code: string; message: string }` where `code` is machine-readable and `message` is operator-facing. No partial inserts on any blocked/error path.

**HTTP surface (versionless, consistent with current `/health` style) — binding status codes:**

#### `POST /projects`

| Status | When | Body |
|---|---|---|
| **201** | Registration success | `ProjectDto` |
| **422** Unprocessable Entity | Eligibility / validation blocked | `ProjectErrorResponse` with one of: `empty_repository_path`, `relative_repository_path`, `repository_not_found`, `repository_not_directory`, `repository_not_readable`, `project_yaml_missing`, `project_yaml_not_regular_file`, `invalid_derived_slug`, `invalid_display_name` |
| **409** Conflict | Uniqueness conflict | `ProjectErrorResponse` with `duplicate_repository_path` or `duplicate_project_slug` |
| **500** Internal Server Error | Unexpected filesystem, Prisma, or infrastructure failure | `ProjectErrorResponse` with a generic safe `code`/`message`; MUST NOT expose additional internal paths, stack traces, or file contents |

#### `GET /projects`

Minimal list of `ProjectDto[]` for empty-state detection on the registration surface—not a discovery-health dashboard.

#### `GET /projects/:id`

| Status | When | Body |
|---|---|---|
| **200** | Project exists | `ProjectDto` |
| **404** | Missing | `ProjectErrorResponse` with `project_not_found` |

No auth headers. CORS/base URL for local web→API follows existing environment pattern (`environment.local`).

- *Alternative considered:* defer all GET listing to `w01-s04`. Rejected — User Story `-003` needs empty vs success outcomes on an operator-visible surface; a minimal list is not a dashboard.
- *Alternative considered:* GraphQL. Rejected — REST matches the Nest/Fastify baseline.
- *Alternative considered:* use 400 for all validation failures. Rejected — 422 for unprocessable eligibility vs 409 for conflicts keeps operator handling deterministic.

### D6 — Minimal Angular registration flow (not dashboard)

Extend `apps/web` with a Spanish-first registration view (PrimeNG inputs/buttons consistent with the shell):

- Empty: form ready (path input; optional display name); if `GET /projects` returns `[]`, show empty-registry copy.
- Loading: disable submit / show progress while request in flight.
- Success: show registered project summary from the `201` body (and refresh minimal list).
- Blocked/error: show explicit reason from the API `code`/`message` payload; do not pretend success.

Do not build multi-column dashboards, discovery-health indicators, or project detail inspection beyond registration confirmation. Routing may replace or sit beside the baseline shell landing content as a single registration entry point.

- *Alternative considered:* API-only with no UI. Rejected — `-003` requires operator-visible outcomes through the console experience.
- *Alternative considered:* full registry table with health columns. Rejected — `w01-s04`.

### D7 — Test strategy and evidence

Jest remains the runner. Evidence under this change’s `evidence/`:

1. **Unit:** preflight cases including empty/relative path, not found, not directory, not readable, missing YAML, YAML not regular file, invalid derived slug, `displayName` over 120 chars, and symlink/alias paths that realpath to an already-registered canonical directory (`duplicate_repository_path`)—temp-dir based where possible without Docker.
2. **API/integration (Testcontainers PostgreSQL):** migrate deploy; successful `POST /projects` against a temp repo fixture that contains `.specpilot/project.yaml` (persisted path is realpath); at least one **422** blocked path (e.g. missing YAML → structured body, no row); concurrent or forced unique-constraint collision mapped to **409** with the correct `code`.
3. **Web:** component/service tests for empty/loading/success/error state handling against mocked API responses (including 422/409/`project_not_found`).
4. Existing health/readiness and `AppMetadata` tests remain green; quality gates (`npm run quality-gates`) must `PASS` before commit/push.

- *Alternative considered:* mock Prisma for the success-path persistence proof. Rejected — registration durability requires a real migrated schema.

### D8 — Security, privacy, observability

- Canonical absolute `repositoryPath` values are operational data in PostgreSQL only; never commit them into portable YAML or fixtures that embed operator home paths into the repo (tests use temp dirs).
- Registration performs metadata/presence/`realpath` reads only; no secret file contents ingested; do not open/read `.env` or key material.
- **500** responses and logs MUST NOT leak stack traces, extra internal paths, or file contents to the client.
- No authentication (single local user unchanged).
- Observability: structured API logs for register success/blocked with slug/id/`code` (not dumping unrelated file contents); HTTP status codes as the primary operator signal.

### D9 — Docs, inventory, lifecycle

After implementation: update `docs/context/**`, regenerate `package-summary.json` if dependencies/scripts change, and document operator commands for API/web registration checks using hyphenated OpenSpec command syntax where OpenSpec commands are referenced. Canonical sync and archive only after Verify exactly `PASS` with operator approval.

### D10 — Uniqueness constraints and concurrency (binding)

- PostgreSQL **unique constraints** on `repositoryPath` and `slug` are the **final** guarantee against concurrent registrations.
- Application-level prechecks improve operator feedback (clear 409 after a read) but **do not** replace those constraints.
- Prisma unique-constraint violations MUST map **deterministically** to HTTP **409** with `duplicate_repository_path` or `duplicate_project_slug` as appropriate.
- Never rely on check-then-insert alone: every insert path MUST handle the uniqueness race (catch constraint failure → 409). No partial success when the race loses.

- *Alternative considered:* precheck-only uniqueness without DB constraints. Rejected — concurrent requests can double-insert.
- *Alternative considered:* serialize all registrations with a global lock. Rejected — DB unique constraints are simpler and correct for local single-process and multi-request cases.

### D11 — Compose host repository visibility (authorized root, read-only)

Compose `api` runs in an isolated filesystem and cannot see macOS host paths by default. For Compose-backed registration, operators MUST bind-mount an **authorized host root** into the API container at the **same absolute path**, read-only, via a **gitignored** `compose.override.yaml` driven by `SPECPILOT_HOST_REPOS_ROOT` in a gitignored `.env`. Tracked templates (`compose.override.example.yaml`, `.env.example`) use placeholders only. Do not mount `/` or the entire home directory. Do not rewrite or persist alternate container-only paths: `repositoryPath` remains the host-compatible realpath. Native macOS API processes need no mount. Recreate only SpecPilot Compose resources; never touch `axioma-db-dev`.

- *Alternative considered:* mount the entire host filesystem. Rejected — excessive privilege.
- *Alternative considered:* rewrite host paths to a container alias and persist the alias. Rejected — breaks host-compatible identity and operator UX.
- *Alternative considered:* hard-code the operator personal path in tracked Compose files. Rejected — non-portable and privacy-hostile.

## Risks / Trade-offs

- [Basename-derived slug collisions across differently pathed repos with the same folder name] → Unique constraint + `duplicate_project_slug` (409); operator must choose a differently named directory (explicit slug override deferred).
- [Presence-only YAML check accepts invalid YAML content] → Accepted trade-off; `w01-s02` owns parse/schema/versioning and will attach configuration snapshots / status updates.
- [Minimal `GET /projects` mistaken for the product dashboard] → Specs and UI copy frame it as registration empty-state support; discovery-health dashboard remains `w01-s04`.
- [Filesystem adapter reads outside intended repos if operator pastes a broad path] → Local single-user trust model; still fail closed on non-directory/missing YAML; never write.
- [Prisma delta conflicts with canonical “no product domain tables” rule] → Explicit delta on `postgresql-prisma-persistence-baseline` allowing Project only.
- [Angular baseline “no product domain screens” conflict] → Explicit delta allowing this registration surface only.
- [Trailing slashes, redundant segments, or symlink aliases creating duplicate rows] → Binding realpath canonicalization before persist/compare; store only the canonical absolute directory path; symlink textual forms are not additional identities.
- [Concurrent register requests racing past precheck] → DB unique constraints + deterministic Prisma→409 mapping (D10); never check-then-insert without handling the race.
- [`displayName` over max accepted silently or truncated] → Reject with 422 `invalid_display_name`; max 120 enforced in contract, model, and tests.
- [Scope creep into YAML parsing or Git discovery during apply] → Non-goals and exclusions are binding; tasks reject out-of-slice work.

## Migration Plan

1. Extend `packages/shared-contracts` with registration DTOs, `ProjectErrorResponse`, `displayName` max **120**, and validators for the exact `code` set; keep health contracts intact.
2. Add Prisma `Project` model + additive migration with **unique** `repositoryPath` and `slug`, `displayName` length bound to 120; keep `AppMetadata`; apply via `prisma migrate deploy` in Compose and tests.
3. Implement filesystem preflight port/adapter using **realpath** canonicalization (D2/D3) and Projects application service with fail-closed outcomes and D10 race handling on insert.
4. Expose `POST /projects`, `GET /projects`, `GET /projects/:id` from Nest/Fastify with the exact status/`code` matrix in D5; wire `ProjectsModule` into `AppModule`.
5. Add Angular registration flow with Spanish empty/loading/success/blocked-error states calling the API via existing local environment base URL.
6. Add unit + Testcontainers + web tests (including symlink→same realpath duplicate and unique-constraint→409); capture evidence under this change’s `evidence/`.
7. Run `npm run quality-gates`; update docs/context and package summary as needed.
8. With operator approval after reported validations: commit on `main` (and push if requested).
9. With operator approval: Verify exactly `PASS`, sync canonical specs (new + deltas), archive.

**Rollback:** revert the slice’s commits on `main`; roll back or reset only the local SpecPilot database/volume as already documented for Compose; no remote/shared production rollback. MUST NOT touch foreign Docker resources (e.g. `axioma-db-dev`).
